refactor: improve system files handling and CLI interface

This commit improves the handling of system files in the torrent creation process,
making the behavior more consistent and intuitive across the codebase.

Key Changes:
1. CLI Interface:
   - Changed flag from --skip-system-files to --include-system-files
   - Made skipping system files the default behavior (security first)
   - Updated help text to clarify the default behavior
   - Fixed conflicting action/default values in argparse configuration

2. Internal Changes:
   - Kept skip_system_files as the internal variable name (True by default)
   - Using action=store_false with --include-system-files to properly toggle behavior
   - Added clarifying comments in commands.py about system files handling

3. Documentation Updates:
   - Updated README.md to reflect new CLI flag and default behavior
   - Clarified security implications of system files in documentation
   - Added examples showing --include-system-files usage
   - Improved consistency in configuration options documentation

4. Test Updates:
   - Updated test_global_torrent_options to verify default behavior
   - Added explicit test for --include-system-files flag
   - Ensured test_global_torrent_options_large_piece_size uses correct defaults
   - Fixed test assertions to match new behavior

Technical Details:
- Default behavior: system files are skipped (skip_system_files=True)
- --include-system-files flag sets skip_system_files=False
- Uses argparse's store_false action for intuitive flag behavior
- Maintains backward compatibility with existing config structures

Security Implications:
- System files (.DS_Store, .nfs, etc.) are now skipped by default
- Explicit opt-in required to include system files (--include-system-files)
- Aligns with principle of secure defaults
- Prevents accidental inclusion of potentially sensitive system files

This change improves security by defaulting to skip system files while
maintaining flexibility for users who explicitly need to include them.
